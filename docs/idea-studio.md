# Idea Studio — 2026-09-29

Conversation -> immediate one-page draft -> revision history -> explicit exact-revision confirmation -> independent A0/B0 -> A1/B1 -> F -> N (novelty and approved-intent gate). Failed novelty/intent gets one bounded rewrite. No private model reasoning is exposed; public review summaries are persisted independently and polled every four seconds.

Daily issue keys remain YYYY-MM-DD. Conversation issues use YYYY-MM-DD--<24-char-id>; issueDate remains a calendar date. Ownership comes exclusively from the authenticated user. Daily issues and confirmed briefs have independent keys, and confirmation is idempotent. Input revisions and expiring leases guard parallel updates. Maximum 30 chat generations/day, 6 issue runs/day, 62/month; council at most 10 calls/run and 620/month. A user-requested follow-up may resemble prior work, but original ambition must survive.

Knowledge taxonomy is a pinned copy of ChunkingExpress data/curriculum.v3.json (10 domains, 160 topics), with original stable IDs and display numbers. UI choices and exclusions are per user. Formats are an independent axis. Category focus rotates toward less recently used permitted domains. Approved knowledge snapshots are retrieved using lexical relevance and category diversity, max 4 documents/32k characters; no embedding-based search is claimed. Source limitations remain intact. RAG membership is never treated as evidence of personal taste.

The source app's approved knowledge map sends a user-selected snapshot (max 80 documents per send) using postMessage with exact source/target origin, window identity, and a one-time nonce. Firebase tokens never leave ChunkingExpress. The authenticated Blanket server validates schema, categories and sizes, stores an immutable per-user bundle, and atomically switches its pointer. A new import replaces the current selection, preserving prior snapshots and pitch evidence. This release is explicit snapshot transfer, NOT unattended synchronization or a live Firebase query service. It requires both apps to be open and signed in as needed. Source UI reads verified local approved units plus up to 10 recent central dispatch batches on request; it does not claim to enumerate the whole Firebase corpus. Source examples are excluded.

No new Firebase project, credentials, or production SajuGrap RAG mutation is required. The category map is visible in both apps; source taxonomy remains authored in ChunkingExpress. Imported topic tagging changes the exported snapshot only, not the original unit. A future authenticated service connector should replace manual transfer when source-side scoped read credentials are configured.

Validation: account/revision boundaries, no automatic execution before approval, simultaneous A/B partial progress persistence, semantic rejection bounded rewrite, RAG ownership/exclusions, existing Blanket regression tests. Real provider quality and authenticated cross-window transfer require a signed-in browser check.
