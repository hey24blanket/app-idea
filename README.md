# IDEA VAULT · Daily Pitch

매일 한 장의 개인 기획서. Desk / AI Agora의 A0·B0 → A1·B1 → F 검토 방식으로 관심·현재 작업·명시적 피드백을 읽고, 선택한 제안을 Markov Blanket의 MD 초안으로 내보냅니다.

## 실행

Node 24+, `npm ci`, `npm run dev`, `npm test`, `npm run build`. Vercel에서 Vite 프런트와 Node 서버 함수 `api/vault.js` / `api/cron.js`를 배포합니다. 개발 서버는 Vite UI만 제공하며 실제 API는 Vercel 환경에서 확인합니다.

## 초기 저장소 결정

설계 v1의 Firebase 후보 대신, 첫 두 사람용 릴리스는 `hey24blanket/markov-blanket-data` 비공개 저장소를 사용합니다. 새 서비스 계정 설정 없이 기존 GitHub 연결로 시작하기 위한 결정입니다. 모든 요청은 서버가 계정 세션과 소유자를 확인한 뒤 저장소에 접근합니다. DB 어댑터는 `server/store.cjs`로 분리했습니다. 앱에 공개 데이터 경로나 임의 저장소 접근 API는 없습니다.

저장소가 공개 상태이면 서버가 동작을 거부합니다. SHA 비교와 재시도로 동시 쓰기 충돌을 처리합니다. `state.json`에는 계정의 scrypt 해시, 해시된 세션·초대, 관심, 간단한 목차와 최근 작업 상태가 있습니다. 문서 원본은 `pitches/{uid}/{date}.json`에 따로 저장합니다. 원본은 덮어쓰지 않습니다. 개인 데이터는 앱 소스 저장소나 웹 배포에 포함하지 않습니다.

Git 이력에는 과거 값이 남습니다. 삭제·규모 확장·일반 공개 서비스 전환 전에 Firestore/Postgres로 마이그레이션하고 삭제 정책을 구현해야 합니다. 현재 서버는 두 사람의 작은 작업 공간을 위한 초기 구현이며 고빈도 쓰기용 DB 대체 제품이 아닙니다.

## 모델과 Desk 출처

`server/council.cjs`는 `hey24blanket/desk-app/api/cycle.js`의 A0/B0 → A1/B1 → F 순서를 bounded daily 모드로 이식했습니다. 원본 blob: `b0a1ee070b060e9838a54823ede6792553c1f527`. 기존 Desk 배포를 변경하거나 공개 엔드포인트에 의존하지 않습니다. 모델·프롬프트·사용량·중간 결과는 문서와 작업 상태에 기록합니다.

자동 코딩/외부 배포를 수행하지 않습니다. 현재 외부 API 실시간 조사 기능은 포함하지 않습니다. 공식 자료를 검색한 것처럼 표현하지 않도록 입력과 프롬프트에서 현재 가격·가용성을 미확인으로 취급합니다. 취향·작업 기록에 기반한 기획이 첫 범위입니다. 의미 기반 90일 중복 비교는 프롬프트로 전달하며, 서버는 동일 제목 해시를 추가 차단합니다.

## 필요한 서버 설정

`.env.example`의 이름을 참고합니다. OpenAI/Gemini 모델 키, 데이터 저장소에 대한 GitHub 읽기·쓰기 키가 필요합니다. 운영에서는 해당 비공개 저장소에만 접근 가능한 fine-grained 토큰을 권장합니다. 기존 광범위 토큰을 쓰는 경우 권한을 더 늘리지 말고 앱 서버 밖으로 노출하지 않습니다.

`CRON_SECRET` 설정 전 예약 API는 401을 반환합니다. VAPID 키 쌍 설정 전 알림 등록을 제공하지 않습니다. 공유 환경변수에 이미 있는 키를 연결하더라도 값은 로그/응답/소스에 기록하지 않습니다. Preview에는 운영 개인 데이터를 연결하지 않는 것이 기본입니다.

## 첫 계정

비공개 데이터 저장소의 초기 상태에 32바이트 난수 초대 토큰의 SHA-256 해시를 등록합니다. 원문 초대 토큰은 커밋하지 않습니다. 사용자는 초대 링크의 `#join=` 값 또는 초대 코드를 이용해 자신의 아이디와 12자 이상의 비밀번호를 정합니다. 이후 소유자가 앱 안에서 아내의 초대 링크를 만들어 직접 전달할 수 있습니다. 각 계정의 프로필·문서·피드백은 분리됩니다.

초대 링크는 fragment로 전달하며 초기 화면에서 주소 기록에서 제거합니다. 세션은 HttpOnly, Secure, SameSite=Strict 쿠키이고 서버에는 해시만 보관합니다. 로그인 실패 잠금과 입력 제한을 둡니다. 비밀번호 재설정 UI는 아직 없으므로 공개 회원가입 서비스로 운영하지 않습니다.

## 예약과 실패 복구

Vercel Cron은 5분 간격으로 due 사용자만 처리합니다. 기본 시각은 서울 09:00이며 1시간 전부터 준비합니다. 사용자가 관심 설정에서 자동 생성을 켜야 활성화됩니다. 중복 실행은 날짜별 작업과 145초 lease로 막고 각 성공한 노드를 보존합니다. 단계별 최대 2회, 하루 한 문서이며 문서 발행 후에만 알림 outbox가 생깁니다.

현재 과금 제한은 일일 호출·출력 토큰 한도와 월간 발행 수에 의한 제한입니다. 통화 단위의 실제 요금 상한은 가격표 확인·정산 어댑터 구현 전이며 사용량 기록과 구분해야 합니다. Vercel 실행·GitHub 요청 비용도 별도입니다.

예약·푸시 성공을 검증한 뒤에만 기존 `.github/workflows/auto_push.yml`의 hourly 스케줄을 해제합니다. 현재 작업 중에는 기존 파일을 보존합니다. 기존 브라우저 `vault_ideas`도 삭제하지 않습니다.

## PDF와 연결

같은 문서에 `@page A4`와 인쇄 스타일을 적용했습니다. 브라우저의 인쇄/PDF 저장을 이용합니다. 자동 서버 PDF 파일 생성·보관은 아직 포함하지 않습니다. 본문 제한을 두었지만 최장 문서의 A4 한 페이지 검증은 브라우저 렌더 기준으로 확인해야 합니다. 생성 실패를 예제 문서로 바꿔 성공처럼 표시하지 않습니다.

‘실행 계획으로 가져가기’는 Markov MD 1.0을 내보냅니다. 실제 일정 추가와 공동 캘린더는 후속 Markov 앱 구현 범위입니다. 이 릴리스가 전체 마코프 블랭킷 기능을 구현했다는 의미는 아닙니다.

## 검증

`npm test`는 소유권 세션, 만료 초대, 날짜 경계, A/B 독립 입력, 실패 복구, 중복 발행·동시 저장, 스키마와 MD 계약을 확인합니다. 모델 실제 호출·Production 환경 연결·알림 수신·최장 A4 인쇄는 별도 실사용 검증 항목입니다. 설정이 없으면 명시적인 준비 상태를 보여주며 성공한 척하지 않습니다.
